# v1.0.17

这一版修的是**在线更新**和**右键菜单**的两个缺陷。

## 修复：在线更新报「HTTP 302」

点「检查更新」或「下载并安装」时会报 `HTTP 302`，**开不开代理都一样**。

原因不是网络，是代码：更新用的请求**没有跟随重定向**，只要服务器回 3xx 就直接当成错误。
而 GitHub 的安装包下载地址正是先回 302 再跳到 CDN：

```
github.com/…/releases/download/v1.0.17/xxx.exe
  --302--> release-assets.githubusercontent.com/…
  --200--> 文件
```

所以「检查更新」这一步往往正常（那个接口直接回 200），一到**真正下载**就失败。
现在会正常跟随重定向（最多 5 跳，防止死循环）。

> 顺带修掉一个更隐蔽的问题：下载时**第一块数据可能被丢掉**。
> 之前统计下载进度的那段代码会把响应切成「流动模式」，而真正写文件的一方要晚一步才开始读 ——
> 先到的分片就丢了。更新包有 90MB，分片来得慢，所以一直没暴露；
> 但理论上**下载下来的安装包可能是坏的**。现在改成经过一层中转，计数与交付互不干扰。

## 修复：右键菜单关不掉

歌曲右键菜单打开后，**点空白处、按 Esc、滚轮都关不掉**，只能选一项让它自己关。

原因是关闭处理写成了 `ctx.visible = false` —— `ctx` 是一个 ref，这种「对 ref 的属性赋值」
不会改到真正的响应式对象，等于什么都没做。现在统一走显式函数。

同样的写法在**歌单选择器**上也有（歌曲列表页与在线搜索页各一处），一并修了。

> 另外，Esc 现在由菜单自己处理，不再只依赖那个延迟挂载的全局监听 ——
> 之前只要那个监听没挂上，键盘用户就**完全无法关闭菜单**。

## 升级提示

- **数据不会丢**：安装版升级时曲库、歌单、收藏、缓存、代理设置都会保留。
- **卸载会连同数据一起删除**，卸载前请先备份 `data/` `music/` `cache/` `sources/` 这几个目录。
- 免安装版（zip）直接解压覆盖即可。

> ⚠️ 如果你之前用「下载并安装」失败过，这次请手动下载安装包升级一次；
> 升级到这个版本之后，之后的自动更新就会正常了。
