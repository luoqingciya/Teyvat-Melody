# v1.0.23

这一版做的是**让出问题时能被查出来**。不修具体某个 bug，而是把「查不到原因」这件事本身解决掉。

## 之前的问题

后台服务（Python 进程）如果崩了：

- 它的输出被**整个丢弃**（启动时用的是 `stdio: "ignore"`）—— Python 的报错信息一个字都不留；
- 崩溃时只往控制台打了一行，而**打包后的应用没有控制台**，等于没打；
- 不重启、也不提示。用户看到的就是**「用着用着所有操作都没反应了」**。

前端也一样：Vue 报错、未捕获异常、没处理的 Promise 拒绝，全都只出现在用户自己的控制台里 ——
打包后等于不存在。界面坏掉时，我们连是哪个页面、哪一行都不知道。

## 现在

**① 有日志文件了** —— `<数据根>/logs/app.log`

- 按大小轮转（1MB × 3 份），常驻托盘开几天也不会把磁盘写满；
- 后台服务的输出全部记录，**并按其内容判定级别**（Flask 的启动横幅和访问日志算 info，
  真正的 traceback 才是 error —— 否则满屏红字反而把报错淹了）；
- 前端的三类全局错误也一并记进去，并标注来源是 `[renderer]`。

**② 后台服务崩了会自动重启，并告诉你**

- 崩溃原因（退出码 / 信号）与后台的报错都会进日志；
- 界面上会弹提示：「后台服务意外退出，正在自动重启（第 N 次）」，恢复后再提示一次；
- **60 秒内最多重启 3 次** —— 避免「崩→重启→崩」的死循环一直啃 CPU。
  超过上限就停下来，并提示你去看日志。

**③ 日志在哪儿看得到**

设置 → 关于与更新 → **日志目录**，有「打开日志目录」按钮，直接跳过去。

> 以后遇到问题，把 `logs/app.log` 一起发过来，基本就能直接定位。

## 升级提示

- **数据不会丢**：安装版升级时曲库、歌单、收藏、缓存、代理设置都会保留。
- **卸载会连同数据一起删除**，卸载前请先备份 `data/` `music/` `cache/` `sources/` 这几个目录。
- 免安装版（zip）直接解压覆盖即可。

> 如果你还在 v1.0.17 之前，请**手动下载安装包**升级一次 ——
