# v1.0.24

新增**备份与恢复**。

README 里一直写着「卸载会连同数据一起删除，请先备份」—— 但应用里并没有任何备份手段，
等于把这件事全推给用户自己去翻目录。现在有了。

## 设置 → 关于与更新 → 备份与恢复

**导出备份** —— 选个位置存一个 zip，里面是：

- **曲库、歌单、收藏**（数据库）
- **代理、快捷键等配置**
- **导入的源脚本**及其启用状态
- **各项设置**（主题、字号、播放选项、音量…）

**从备份恢复** —— 选一个备份包，确认后覆盖当前数据并自动重启。

## 不在备份里的（以及为什么）

- **你的音乐文件**：体积大，而且那是你自己的文件，不该混进备份包里；
- **音频缓存**：几十 MB，随时能重新下回来；
- 日志、浏览器缓存：没有备份价值。

所以备份包通常只有几百 KB，很小，方便长期留着或换机器时带走。

## 一个容易被忽略的正确性问题

备份数据库**不能直接拷贝 `library.db` 文件**：后端一直在跑，SQLite 用的是 WAL 模式，
最近的写入可能还在 `-wal` 里没并进主库 —— 直接拷会得到一个「旧」的库；
把 `-wal`/`-shm` 一起拷，又可能正好拷在写入中途，得到一个**撕裂的库**。

备份的全部意义就是「能还原」，拷出一个坏库等于白做。所以这里改成让 SQLite 自己
导出一份一致快照（`VACUUM INTO`），顺带还把库压实了。

> 万一快照取不到，会退回直接拷贝，并**明确提醒你**这次备份里的曲库可能不是最新的 ——
> 而不是让你以为备份一定是完整的。

## 恢复时的两个安全考虑

- **会先停掉后端再写数据**，写完自动重启 —— 数据库不会被「在一个正在使用的进程底下」换掉；
- **会拒绝越界路径**：备份包可能是别人给的，里面的 `../` 不能写到数据根之外。

## 升级提示

- **数据不会丢**：安装版升级时曲库、歌单、收藏、缓存、代理设置都会保留。
- **卸载会连同数据一起删除** —— 现在你可以先在「设置 → 关于与更新」里导出一份备份。
- 免安装版（zip）直接解压覆盖即可。

> 如果你还在 v1.0.17 之前，请**手动下载安装包**升级一次 ——
> 那些版本的「下载并安装」是坏的，修不了自己。
